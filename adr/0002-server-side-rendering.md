# Серверный рендеринг на Thymeleaf вместо одностраничного приложения

## Контекст и постановка задачи

Интерфейс должен быть русскоязычным и адаптивным при ширине от 360 до 1920 пикселей (REQ-INT-001) и содержать списки, карточки, формы счетов и дашборд (мокапы, рисунки 3–7 SRS). Как формировать пользовательский интерфейс: на сервере или в отдельном клиентском приложении?

## Драйверы решения

* Объём работ: исполнитель один, 60 часов на итерацию.
* Один язык и один артефакт сборки (REQ-BUILD-001).
* Защита от межсайтовых атак: CSRF и экранирование вывода (REQ-SEC-003).
* Нет требований к интерактивности, кроме перетаскивания карточек на доске статусов (перенесено в версию 1.1).

## Рассмотренные варианты

* Thymeleaf (серверный рендеринг) с точечным JavaScript
* React с REST API
* Vaadin

## Итог решения

Выбранный вариант: «Thymeleaf с точечным JavaScript», потому что он исключает отдельный API и отдельную сборку клиента, встроенно экранирует вывод и интегрируется с токенами CSRF Spring Security.

### Последствия

* Хорошо, потому что меньше кода: нет слоя DTO/API для интерфейса, нет второго набора тестов.
* Хорошо, потому что автоматическое экранирование выводимых данных (REQ-SEC-003).
* Плохо, потому что богатые интерактивные элементы (доска статусов с перетаскиванием) потребуют дописывать JavaScript.
* Плохо, потому что смена технологии интерфейса позже потребует разработки REST API.

### Подтверждение

Инспекция шаблонов: отсутствие небезопасного вывода (`th:utext`); автотест отправки формы без CSRF-токена.

## Плюсы и минусы вариантов

### Thymeleaf с точечным JavaScript

* Хорошо, потому что быстрая разработка форм и списков.
* Нейтрально, потому что адаптивность обеспечивается CSS.

### React с REST API

* Хорошо, потому что богатый интерфейс.
* Плохо, потому что вдвое больше работ: API, клиент, авторизация по токенам.

### Vaadin

* Хорошо, потому что интерфейс пишется на Java.
* Плохо, потому что тяжёлая библиотека, сложнее печатные страницы и мокапы.

## Дополнительная информация

Связанные требования: REQ-INT-001, REQ-SEC-003, REQ-BUILD-001. Представления SDD: 002-composition, 005-interface. В версии 1.1 доска статусов (REQ-FUNC-014) реализуется поверх тех же маршрутов `POST /projects/{id}/status`.
