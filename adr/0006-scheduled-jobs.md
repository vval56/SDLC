# Напоминания и проверка просрочки средствами `@Scheduled`

## Контекст и постановка задачи

Система должна ежесуточно переводить выставленные счета в статус «Просрочен» (REQ-FUNC-013) и в 09:00 по Europe/Minsk отправлять напоминание о приближающихся сроках (REQ-FUNC-015). Чем запускать периодические задачи?

## Драйверы решения

* Единственный экземпляр приложения, нет кластера.
* Минимум дополнительных контейнеров (REQ-INST-001, REQ-COST-001).
* Отправка писем не должна влиять на работу остального приложения (REQ-INT-003).

## Рассмотренные варианты

* Spring `@Scheduled` внутри приложения
* Quartz
* Внешний планировщик (cron в контейнере, вызывающий защищённую конечную точку)

## Итог решения

Выбранный вариант: «Spring `@Scheduled`», потому что для одного экземпляра он не требует дополнительных зависимостей и хранилища заданий.

### Последствия

* Хорошо, потому что работает «из коробки» и тестируется вызовом метода.
* Плохо, потому что при остановке приложения в момент срабатывания задача пропускается; для REQ-FUNC-013 задача идемпотентна и догоняет пропущенное при следующем запуске.
* Плохо, потому что при запуске нескольких экземпляров письма дублировались бы; это зафиксировано как ограничение «один экземпляр» (SRS 3.5.3).

### Подтверждение

Модульные тесты задач с подменой часов (`Clock`); интеграционный тест «письмо не отправляется при отсутствии сроков».

## Плюсы и минусы вариантов

### Spring `@Scheduled`

* Хорошо, потому что простота.
* Нейтрально, потому что часовой пояс задаётся параметром `zone = "Europe/Minsk"`.

### Quartz

* Хорошо, потому что хранение заданий и кластер.
* Плохо, потому что избыточен для одного экземпляра и добавляет таблицы.

### Внешний планировщик

* Хорошо, потому что работает независимо от JVM.
* Плохо, потому что ещё один контейнер и защищённая конечная точка.

## Дополнительная информация

Связанные требования: REQ-FUNC-013, REQ-FUNC-015, REQ-INT-003. Представления SDD: 007-state, 008-patterns. Пересмотреть при появлении нескольких экземпляров приложения.
